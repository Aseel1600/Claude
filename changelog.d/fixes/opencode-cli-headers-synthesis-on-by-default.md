- **fix(providers):** OpenCode CLI identity-header synthesis is now ON by default for opencode/opencode-zen/opencode-go — sending the official fingerprint (`User-Agent: opencode/latest/1.18.18/cli`, `x-opencode-client: desktop`, `x-opencode-project: /opencode`, fresh request/session UUIDs) turns opencode.ai's free-tier `FreeUsageLimitError` 429 into a 200 on the same datacenter egress IP (live-verified: see PR #10357). Previously opt-in via `OPENCODE_SYNTHESIZE_CLI_HEADERS=true`, the default now synthesizes unless explicitly disabled with `OPENCODE_SYNTHESIZE_CLI_HEADERS=false`. Client-supplied `x-opencode-*` headers still win, EXCEPT User-Agent — a non-CLI client UA (e.g. curl, SDKs) is still replaced with the CLI UA because the free tier rejects generic client UAs from datacenter IPs. All values remain env-overridable (`OPENCODE_USER_AGENT` / `OPENCODE_CLIENT` / `OPENCODE_PROJECT`, or `<PROVIDER>_USER_AGENT`). Docs: `.env.example` updated to match. (#5997 follow-up)
